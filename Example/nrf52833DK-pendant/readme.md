# Project structure design

```
Example/nrf52833DK-pendant/
├── app/
│   ├── package_main/        # System entry point and top-level manager
│   ├── package_bus/         # Zbus channels + shared data contracts (Glue Layer)
│   ├── package_ui/          # Former package_lvgl_demo, UI Layer (Port + Presenter + View)
│   │   ├── port/            # Owns the LVGL render thread (lv_timer_handler loop) and the
│   │   │                    # ui_lock()/ui_unlock() mutex; drives display power-on via
│   │   │                    # hardware/package_display once the panel is ready
│   │   ├── presenter/       # Subscribes to Zbus, takes ui_lock(), calls view update APIs,
│   │   │                    # releases ui_lock()
│   │   └── view/            # Pure LVGL widgets and rendering (can be generated by GUI
│   │                        # Guider); assumes the caller already holds ui_lock(), never
│   │                        # locks/unlocks itself
│   └── package_rs485_app/   # Former package_rs485_demo, business logic and protocol layer (Model)
│
├── boards/
│   └── nrf52833dk_nrf52833.overlay
│
└── hardware/
    ├── package_display/     # Display backlight and reset control (rendering is handled primarily by the Zephyr display driver)
    └── package_rs485/       # Low-level UART transmit/receive wrapper and RS-485 transceiver RE/DE control
```

## UI concurrency rule (`package_ui`)

LVGL is not thread-safe, so `package_ui` owns a single `k_mutex` behind
`ui_lock()` / `ui_unlock()`, exposed by the `port` sub-module:

- **`port`**'s render thread is the only place that periodically calls
  `lv_timer_handler()`, always wrapped as `ui_lock()` → `lv_timer_handler()` →
  `ui_unlock()` on every tick.
- **`presenter`** is the only other caller allowed to take the lock: it wraps
  each batch of `view` update calls as `ui_lock()` → `view_xxx_update(...)` →
  `ui_unlock()` after translating a Zbus message into view-model data.
- **`view`** never locks/unlocks itself — it assumes the caller (`port` or
  `presenter`) already holds `ui_lock()`. This avoids recursive-lock bugs and
  keeps `view` a pure, reusable widget layer.
- Any thread outside `package_ui` (business layer, `package_bus`) must never
  call into `view` or touch an `lv_obj_t` directly. It can only publish
  events/data to `package_bus`; `presenter` is the sole bridge that turns
  those into UI updates under the lock.
