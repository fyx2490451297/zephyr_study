## Zephyr的启动时序

`SYS_INIT(init_fn, level, priority)` 宏接收三个参数，后两个参数共同决定了这个函数在系统上电后 **什么时候被调用** 。

1. 第一个维度：启动阶段

   1. `EARLY` / `PRE_KERNEL_1` / `PRE_KERNEL_2`：此时内核还没准备好，只能做极其底层的时钟、内存和 CPU 寄存器初始化。
   2. `POST_KERNEL`：内核（多线程、互斥锁、定时器）刚刚启动，这里通常用来初始化基础硬件驱动（如 I2C、SPI、底层的 GPIO 控制器）。
   3. **`APPLICATION`** ：最高层的阶段。此时所有的底层硬件驱动和系统服务（如日志 Logging）都已经准备就绪。因为 LED 模块属于偏上层的应用组件，所以放在这个阶段。
   4. `main()` 函数：**所有的 `SYS_INIT` 跑完之后，系统才会正式进入 `main()` 函数。**
2. 第二个维度：优先级

   在同一个启动阶段（比如大家都在 `APPLICATION` 阶段）里，谁先执行谁后执行呢？这就是优先级数字决定的。

   优先级的范围是  **0 到 99，数字越小，越先执行** 。

   在 Zephyr 的官方代码库中，底层的硬件控制器和中间件服务，它们的优先级一般设定在 `40` 到 `60` 之间。
