## 基础编译

* 首次编译

```
west build -b <开发板型号> <目标工程所在的路径>
```

注：`-b` (board) 用于指定目标板。只有在第一次编译，或者想换一块开发板（比如换成 `stm32f4_disco`）时才需要加这个参数。

* 增量编译

```
# 必须在包含 build 目录的层级运行，或者在应用根目录运行
west build
```

注：一旦用 `-b` 成功编译过一次，`west` 就会把配置缓存在默认的 `build` 文件夹中。之后你修改了 `.c` 或 `.h` 文件，只需敲这俩单词，它会自动判断依赖并极速增量编译。

## 清理与强制重编

当修改了  **`prj.conf` (Kconfig)** 、**`CMakeLists.txt`** 或是 **设备树 (`.overlay`)** 时，普通的增量编译往往会失效或产生玄学 Bug，此时必须介入清理。

* 编译前自动深度清理

```
west build -p always -b <开发板型号> <目标工程所在的路径>
```

注：`-p` 代表 pristine（崭新的）。`always` 意味着在本次编译前，直接删掉旧的构建树重新生成 CMake 缓存。防脱发利器。

* 仅清理生成的目标文件

```
west build -t clean
```

注：这等同于 `make clean`，保留 CMake 配置，只删掉编译出来的 `.o` 文件和固件。
